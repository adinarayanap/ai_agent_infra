# Course: Platform Engineering & Agentic Infrastructure

This is an instructional guide for the **Governed AI Infrastructure Deployment Platform**. As your Cloud Infrastructure Instructor, I have structured this curriculum to take you from foundational IaC principles to advanced LLMOps patterns.

---

## 1. The Core Vision
Our platform solves the "Manual Infrastructure Bottleneck" by using an LLM to generate IaC, governed by strict security guardrails.
*   **The Problem**: Cloud infrastructure requires high expertise and manual review, slowing down product teams.
*   **The Solution**: An agent that proposes infrastructure, validated by code-based guardrails, managed by automation.

---

## 2. Sprint 1: Secure Foundation (Days 01–07)

### Module 1: Bootstrap & Identity (Days 01-02)
*   **Concepts**: Remote State, Multi-Account Strategy, IAM Identity Center.
*   **Logic**: Before building AI features, we established the "Root of Trust."
*   **Security**: By moving from single-account to a Sandbox account managed by Identity Center (SSO), we achieved isolation.
*   **Flow**: Terraform state is locked via DynamoDB to prevent concurrent modifications.

### Module 2: Serverless LLM Integration (Days 03-04)
*   **Concepts**: AWS Lambda, Bedrock Converse API, API Gateway/Cognito.
*   **Logic**: Compute must be ephemeral and event-driven.
*   **Security**: Cognito integration ensures only authorized users can prompt the agent. IAM roles follow the *Principle of Least Privilege*—the Lambda function only has permissions to invoke the specific Bedrock model.

### Module 3: Observability & Auditing (Days 05-07)
*   **Concepts**: DynamoDB Audit Log, CloudWatch Metrics/Alarms, SNS.
*   **Logic**: In AI, you cannot fix what you cannot measure. We track the full lifecycle of an infrastructure request: `RECEIVED` -> `COMPLETED`/`FAILED`.
*   **Security**: Auditing is the backbone of governance; every infrastructure proposal generated by the LLM is recorded.

## 3. Sprint 2: The Agent Brain (Days 08–09)

### Module 4: Decoupling & LLMOps (Day 08)
*   **Concepts**: Modularity, Configuration vs. Code, Persona Engineering.
*   **Logic**: Moving from a monolith (`bedrock_hello`) to a dedicated `src/agent/` module.
*   **Why**:
    *   **Testability**: We can now unit-test the agent logic in isolation.
    *   **Scalability**: We can version the prompts independently of the infrastructure code.
    *   **Persona**: The system prompt is now a configuration file, allowing for easy updates to the agent's behavior.

### Module 5: Evaluation Harness (Day 09)
*   **Concepts**: LLM Validation, Compliance Guardrails.
*   **Logic**: Our agent is now a "Planning Assistant." It must *plan* in JSON before *generating* Terraform. This creates an opportunity for a "Validation Gate."
*   **Flow**: User Input -> Agent (Brain) -> JSON Plan -> **Validation Gate (Guardrails)** -> Terraform Generation.

### Module 6: Deterministic Generation & Isolated Validation (Day 10)
*   **Concepts**: Deterministic IaC Generation, Isolated Execution Sandbox, Security Verification.
*   **Logic**: Moving from unconstrained HCL generation to approved deterministic templates for UC1 (Encrypted, versioned, private S3 bucket).
*   **Why**:
    *   **Determinism**: Free-form LLM HCL generation introduces hallucinations and configuration drifts. Templates guarantee exact compliance with security baselines.
    *   **Isolated Validation**: `validate_terraform` executes `terraform fmt -check` and `terraform validate` in isolated temporary directories before code ever reaches deployment pipelines.
    *   **Strict Tool Separation**: Separation of generation tools (`generate_terraform`, `validate_terraform`) from execution tools (`apply_terraform`, `destroy_terraform` are strictly forbidden).
    *   **N1 Negative Control**: Public S3 access is blocked unconditionally at both plan-validation and generation gates.

## 5. Security & Governance Principles

| Layer | Security Mechanism | Why? |
| :--- | :--- | :--- |
| **Access** | Cognito + API Gateway | Ensure verified identity for AI interactions. |
| **Compute** | IAM Roles (Least Privilege) | Prevent the Agent from having full administrative access. |
| **Logic** | JSON-Constraint System Prompt | Force structure and prevent prompt injection (out-of-scope blocking). |
| **Validation** | Validator Module (Day 09) | Guardrail check: Is this plan secure/compliant? |
| **Auditing** | DynamoDB + TTL | Immutable records for operational forensics. |
